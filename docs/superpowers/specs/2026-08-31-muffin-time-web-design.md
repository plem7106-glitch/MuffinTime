# Muffin Time เว็บเกม — Design Spec

วันที่: 2026-08-31

## บริบท

โปรเจกต์นี้คือการทำเกมการ์ด **Muffin Time** (asdfmovie × Big Potato Games) ให้เล่นผ่านเว็บบนมือถือได้ เพื่อนแต่ละคนเข้าห้องผ่านรหัสห้องด้วยมือถือตัวเอง เล่นด้วยกันในสถานที่เดียวกัน (เห็นหน้ากันจริง) แต่ใช้มือถือแทนการ์ดจริงเพราะไม่มีสำรับจริง

**หมายเหตุเรื่องลิขสิทธิ์:** Muffin Time เป็นเกมที่มีลิขสิทธิ์ (TomSka/asdfmovie × Big Potato Games) เนื้อหาการ์ด/ชื่อ/ข้อความที่ใช้ในโปรเจกต์นี้อิงจากเกมจริงเพื่อใช้เล่นส่วนตัวกับเพื่อน ไม่ใช่เพื่อเผยแพร่สาธารณะเชิงพาณิชย์ ไม่ใช้ภาพประกอบ/ตัวละครจาก asdfmovie ใน v1

## เป้าหมาย

- เล่นได้บนมือถือ ผ่านเบราว์เซอร์ (ไม่ต้องติดตั้งแอป)
- รองรับ 3–8 คนต่อห้อง
- คงกติกาและเนื้อหาการ์ดให้ใกล้เคียงเกมจริงที่สุด (231 ใบ: Action 138, Counter 40, Trap 53)
- ไม่มีประสบการณ์เขียนเว็บมาก่อน → เน้นง่าย ฟรี ไม่ต้องดูแลเซิร์ฟเวอร์เอง
- ภาษา UI: ไทยอย่างเดียว

## สถาปัตยกรรม

- **Frontend:** static web app (HTML/CSS/JavaScript ธรรมดา ไม่มีขั้นตอน build ที่ซับซ้อน) responsive สำหรับหน้าจอมือถือ
- **Backend:** ไม่มีเซิร์ฟเวอร์แยก — ใช้ **Firebase Realtime Database** เก็บ state ของเกม และ **Firebase Hosting** โฮสต์เว็บ (ฟรีทั้งคู่)
- **เนื้อหาการ์ด:** ดึงจาก Google Sheets ที่ publish เป็น CSV (ดูรายละเอียดหัวข้อ "เนื้อหาการ์ด" ด้านล่าง) แทนที่จะ bundle แบบ static อย่างเดียว
- **Logic:** รันฝั่ง client เขียนอัปเดต state ลง Firebase โดยตรง ไม่มี Cloud Functions ใน v1
- **ความปลอดภัย/กันโกง:** ไม่ทำในระดับ production — เล่นกับเพื่อนที่เชื่อใจกัน คนที่แกะ devtools จะเห็น state ทั้งห้องได้ในทางเทคนิค (ยอมรับ trade-off นี้แล้ว)

## ระบบห้องเล่น

- ผู้เล่นคนแรกกด "สร้างห้อง" → สุ่มรหัสห้องสั้นๆ (4 ตัวอักษร) ไว้แชร์
- ผู้เล่นคนอื่นกรอกชื่อเล่น + รหัสห้องเพื่อเข้าร่วม ไม่ต้องสมัครสมาชิก
- เก็บ player id ไว้ใน localStorage ของเครื่อง เพื่อให้รีเฟรชหน้า/หลุดการเชื่อมต่อแล้วกลับเข้าห้องเดิมได้ในสถานะเดิม
- สถานะห้อง: `lobby` (รอผู้เล่น) → `playing` → `ended`
- โฮสต์ห้อง (คนสร้างห้อง) เป็นคนกด "เริ่มเกม" เมื่อมีผู้เล่นครบ 3–8 คน

### โครงสร้างข้อมูลใน Firebase (แนวคิดคร่าวๆ)

```
/rooms/{roomCode}/
  status
  hostId
  turnOrder: [playerId, ...]
  currentTurnIndex
  direction: 1 | -1
  muffinTimeTarget: 10       // เปลี่ยนได้ด้วยการ์ด Time of Death
  drawPile: [cardId, ...]
  discardPile: [cardId, ...]
  log: [{ts, text}, ...]     // feed เหตุการณ์ ให้ผู้เล่นตามทันว่าเกิดอะไรขึ้น
  players/{playerId}/
    name
    hand: [cardId, ...]
    traps: [cardId, ...]     // สูงสุด 3 ใบ
    connected
    hasCalledMuffinTime
```

## ระบบเทิร์น

1. (ไม่บังคับ) วางเทรป 1 ใบจากมือ คว่ำหน้า — ถ้ามีเทรปอยู่แล้ว 3 ใบ ต้องทิ้งใบเก่าก่อน
2. เลือกอย่างใดอย่างหนึ่ง: **จั่ว 1 ใบ** หรือ **เล่น Action 1 ใบ**
3. ระบบเช็คเงื่อนไขชนะอัตโนมัติตอนเริ่มเทิร์นของผู้เล่นแต่ละคน: ถ้ามีการ์ดในมือ = `muffinTimeTarget` (ปกติ 10) พอดี → ขึ้นปุ่ม "It's Muffin Time!" ให้กดประกาศ
4. ถ้าประกาศไปแล้วในเทิร์นก่อนหน้า และยังมีจำนวนการ์ดเท่าเดิมตอนเริ่มเทิร์นถัดไป → ชนะทันที

## การจัดการเอฟเฟกต์การ์ด (231 ใบ)

การ์ดแต่ละใบเก็บเป็นข้อมูล (`data/cards.json`) ไม่ใช่โค้ดแยกทีละใบ แบ่งเป็น 3 กลุ่มตามวิธี resolve:

1. **กลไกล้วน** (จั่ว/ทิ้ง/ขโมย/สลับมือ/ข้ามเทิร์น/กลับทิศ ฯลฯ) — ระบบทำอัตโนมัติผ่านชุดฟังก์ชันกลาง (primitive) ประมาณ 20 แบบ เช่น `draw(player, n)`, `discard(player, n)`, `steal(from, to, n)`, `skipTurn(player)`, `reverseDirection()`, `swapHands(a, b)` การ์ดแต่ละใบอ้างอิง primitive + พารามิเตอร์ของตัวเอง
2. **มินิเกม/ต้องมีคนตัดสิน** (จ้องตา, เป่ายิ้งฉุบ, งัดข้อ ฯลฯ) — ระบบโชว์ข้อความการ์ด + ปุ่มให้เลือกผลลัพธ์ (เช่น "ใครชนะ") แล้วใช้ primitive ข้างต้นกับผลลัพธ์นั้น
3. **โซเชียล/อัตนัยล้วน** (เงื่อนไขอิงข้อเท็จจริงในชีวิตจริง เช่น "ทุกคนที่เลี้ยงแมว", หรือ trigger จากคำพูด/พฤติกรรม) — ระบบโชว์ข้อความการ์ดเฉยๆ แล้วให้ผู้เล่นปรับจำนวนการ์ดของตัวเอง/คนอื่นด้วยปุ่ม +/- แบบทั่วไป (พึ่งความซื่อสัตย์กันเอง เหมือนเกมจริง)

**Trap:** วางคว่ำหน้า เจ้าของกดปุ่ม "เปิดกับดัก" เองเมื่อสังเกตว่ามีคนทำเงื่อนไขจริงในห้อง แล้วระบบ apply เอฟเฟกต์ตามกลุ่ม 1–3 ข้างต้น

**Counter:** เล่นสวนได้ทุกเมื่อ — หลัง Action ถูกเล่นหรือ Trap ถูกเปิด ระบบเปิด "ช่วงเวลาตอบโต้" สั้นๆ ให้ผู้เล่นคนไหนก็ได้เล่น Counter จากมือ ก่อนเอฟเฟกต์จะ apply จริง

## ขอบเขต v1 (สิ่งที่ตัดออกก่อน)

- ไม่มีระบบสมัครสมาชิก/บัญชีถาวร — ใช้แค่ชื่อเล่น + รหัสห้อง
- ไม่มีโหมดดูอย่างเดียว (spectator)
- ไม่มีสถิติ/ประวัติเกมข้ามครั้ง
- ไม่มีภาพประกอบ/ธีมภาพสไตล์ asdfmovie — ใช้ UI เรียบๆ อ่านง่ายบนมือถือ
- ต้องเปิดแท็บเบราว์เซอร์ค้างไว้ระหว่างเล่น ไม่มี push notification
- ไม่ทำ Cloud Functions/anti-cheat ใน v1

## การทดสอบ

- Unit test (Vitest) สำหรับฟังก์ชันกลไกหลัก: จั่ว/ทิ้ง/ขโมย/สลับมือ/เช็คเงื่อนไขชนะ/ลำดับเทิร์น
- ส่วน UI และการ์ดกลุ่มโซเชียล ทดสอบด้วยการเล่นจริงกับเพื่อนหลังพัฒนาเสร็จ (ไม่ใช้ automated e2e ใน v1)

## เนื้อหาการ์ด

รายชื่อการ์ดทั้งหมด (ภาษาอังกฤษ + คำแปล/ชื่อไทย + ข้อความเอฟเฟกต์ภาษาไทย) มีต้นทางสองที่:

- **`data/cards.json`** — สำเนาที่ bundle มากับแอป ใช้เป็น fallback ถ้าดึงจาก Google Sheets ไม่ได้ (เช่น ออฟไลน์ หรือ Sheet โดนลบ/เปลี่ยนสิทธิ์) และใช้เป็นข้อมูลตั้งต้นตอนพัฒนา
- **Google Sheets (แหล่งข้อมูลจริงตอนเล่น)** — คุณแก้ไขเนื้อหาการ์ดได้ที่ Sheet โดยตรง แอปจะดึงมาใช้สดๆ ทุกครั้งที่เริ่มเกม ผ่านขั้นตอนนี้:
  1. เปิด Google Sheet → **File → Share → Publish to web** → เลือกแท็บที่มีรายการ์ด → format **CSV** → Publish
  2. จะได้ลิงก์ CSV สาธารณะ (ดูอย่างเดียว แก้ไขไม่ได้จากลิงก์นี้)
  3. แอปจะ `fetch()` ลิงก์นี้ตอนโหลดหน้า แปลงเป็นรายการการ์ด ถ้า fetch ล้มเหลวจะ fallback ไปใช้ `data/cards.json` แทนอัตโนมัติ

**ลิงก์ CSV ที่ใช้จริง (ยืนยันแล้วว่า fetch ได้ และข้อมูลตรงกับ `data/cards.csv` ทุกแถวทุกฟิลด์ 231/231 ใบ เทียบด้วย `code` แล้ว ไม่มีขาด/ไม่มีเพี้ยน):**
```
https://docs.google.com/spreadsheets/d/e/2PACX-1vRoB5uoPb0NOmZAr7G9t2CVzOgJI26OYMgA4ugyqwtaC5fXSaRu-32W7gPqyIAkgZp1r-04sJTj9FC4/pub?output=csv
```
หมายเหตุ: ลิงก์นี้ 307-redirect ไปยัง URL เซ็นชั่วคราวทุกครั้งที่เรียก (`doc-*-sheets.googleusercontent.com/...`) — ห้าม hardcode URL ปลายทางที่ redirect ไป ต้อง fetch จากลิงก์ `pub?output=csv` ข้างต้นเสมอ เพราะ `fetch()` ตามด้วย browser จะ follow redirect ให้อัตโนมัติอยู่แล้ว คอลัมน์ปัจจุบันคือ `type,name_en,name_th,effect_th,code` (231 แถว ตรงกับ `data/cards.csv` — `code` คือ unique ID ของการ์ด รูปแบบ A01–A138 / C01–C40 / T01–T53 ใช้เป็น card id ในแอปได้เลย)

Sheet นี้ใช้เก็บ **เนื้อหาการ์ดเท่านั้น** ไม่ใช่ state ของเกมที่กำลังเล่นอยู่ (มือผู้เล่น/เทิร์น/กองจั่ว) ซึ่งยังอยู่ใน Firebase Realtime Database ตามเดิม เพราะ Sheets ไม่เหมาะกับการอ่าน/เขียนพร้อมกันหลายเครื่องแบบเรียลไทม์

ยังไม่ได้ระบุ execution tier (1/2/3) หรือ primitive ต่อใบในทั้งสองแหล่ง — งานนั้นเป็นส่วนหนึ่งของ implementation plan ขั้นถัดไป (จะเพิ่มเป็นคอลัมน์ในทั้ง Sheet และ `cards.json` ให้ตรงกัน)
